# 1. データとタイミング規約

## 1.1 セットアップ

| 項目 | 規約 |
|---|---|
| ベンチマーク | MSCI India（`universe` の `size` ∈ {1, 2}） |
| ユニバース | MSCI India IMI（`size` ∈ {1, 2, 3}）。毎月再構築（サバイバーシップなし） |
| 評価リターン | `barra/rtn/{t}.pkl` の `lag == 1`（区間 (t, t+1] の単月）。現地通貨 INR・配当込み・% 表記なので /100 |
| IC 減衰用 | 同 `lag == h`（h ヶ月先の**単月**リターン、区間重複なし） |
| 評価期間（コア） | **200701〜202607**。2006年以前はユニバースが 17〜60 銘柄しかなく分位あたり 3〜12 銘柄になるため除外 |
| 欠損センチネル | `factor/core` / `universe` の数値 ≤ −1e8 は NaN に置換 |

検証済みのデータ対応関係:

- `barra/rtn` の `lag=0` ≒ `universe.drtn`（配当込み・現地通貨）に最も近い（相関 0.9998）
- `rtn/{t}.pkl` の `lag=1` は `rtn/{t+1}.pkl` の `lag=0` と厳密一致（将来リターンの取り違えなし）
- 最終月（202607）は先行リターンが存在しないため分位分析から自動除外

## 1.2 パネル構築（`factorlab.data.build_panel`）

`(yyyymm, bid)` の MultiIndex。毎月 `universe`（size 1-3）× `factor/core` × `barra/rtn(lag=1)` を結合し、

- `in_bench`: size 1-2 フラグ
- `sector`: GICS 上2桁（その月の分類 = PIT）
- `log_cap`: log(浮動株調整後時価総額 USD) — サイズ中立化用

を付与する。

## 1.3 AI・オルタナティブ（`factorlab.altdata`）

| データ | 時点 t のスコア |
|---|---|
| `factor/alt/{id}/` | ファイル t のうち **`effective_yyyymmdd` ≤ t の月末**のレコード（銘柄ごとに発効日最新）。発効日ベースの PIT |
| `factor/ai/` | 月 t 内で最後に観測された日次値（月末スナップショット）。元々クロスセクション Z（±3.2 クリップ） |

- alt の評価開始は 201301（NAM ESG の最古 201302 に合わせる）。TVL のみ 200701 から利用可
- AI は 201608〜202604。**ベンチマーク銘柄カバレッジ 99%**・時価総額ベースでユニバースの 84〜86% だが、
  銘柄数ではユニバースの 32%（size 3 は 12%）→ 実質「大型・中型内の選別シグナル」
- ファクター定義の重複名（factor_id 342/343）は `_342` / `_343` を付けて区別

## 1.4 その他の規約

- `gid`（Global ID）: ①BID 7桁 → BID ②SEDOL 7桁 → SEDOL ③CUSIP 9桁 → CUSIP の優先順位。
  本データでは全期間 `gid == bid`
- `map_code` の `yyyymm` は**文字列**、`fctrtn` の `fcd` も文字列（`exp` 側は int）— 結合時に型を揃える
